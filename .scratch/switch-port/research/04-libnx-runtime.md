# 04 — libnx runtime vs Godot 4.7 core requirements

Ticket: "libnx runtime vs Godot 4.7 core requirements". Date: 2026-10-13.

Scope note: the Godot citations below were read in this worktree, which is on `master` (4.8-dev; `version.py`: major 4, minor 8, status dev). The 4.7.2-stable tag is not present in this clone, so line numbers are master's. The files cited (`core/os/thread.h`, `core/os/mutex.h`, `drivers/unix/os_unix.cpp`, `drivers/unix/file_access_unix.cpp`, `drivers/unix/dir_access_unix.cpp`, `drivers/unix/thread_posix.cpp`, `drivers/unix/net_socket_unix.cpp`, `drivers/unix/ip_unix.cpp`) are the same subsystems in 4.7; treat exact line numbers as approximate for 4.7.2 and re-check before patching.

Toolchain inspected: `/opt/devkitpro/devkitA64` (GCC `aarch64-none-elf-gcc (devkitA64) 16.1.0`, newlib `_NEWLIB_VERSION "4.6.0"` from `aarch64-none-elf/include/_newlib_version.h`), `/opt/devkitpro/libnx` (headers + `lib/libnx.a`; no package DB is present under `/opt/devkitpro`, so the exact libnx release is unrecorded. The headers carry `InfoType_TransferMemoryHint ... [19.0.0+]`, so they are a 2024-or-later release).

Method: static reads of the local headers/archives (`nm`), reads of libnx / nx-hbloader / devkitPro-newlib / libstdc++ sources on GitHub, and a link probe (`scratchpad/linktest/t.cpp`, compiled with the libnx flags `-march=armv8-a+crc+crypto -mtune=cortex-a57 -mtp=soft -fPIE -D__SWITCH__` and linked with `-specs=/opt/devkitpro/libnx/switch.specs -lnx`) that references every libc symbol Godot's unix drivers call, so "resolves"/"undefined" statements below are from the actual linker, not from documentation.

## Summary

1. Threads: `std::thread`, `std::mutex`, `std::recursive_mutex`, `std::shared_mutex`, `std::condition_variable`, lock-free 64-bit `std::atomic`, and dynamically-initialised `thread_local` all compile and link (`_GLIBCXX_HAS_GTHREADS 1`; pthreads come from devkitPro's `libsysbase.a` on top of libnx `__syscall_thread_*`). No thread naming/priority/affinity: `pthread_setname_np`, `pthread_setschedparam`, `pthread_setaffinity_np` are declared but undefined, and `cpu_set_t` does not exist.
2. Stack sizes are the real threading hazard: `std::thread` passes a NULL attr, libnx then gives every thread 128 KiB; the hbloader main thread has 1 MiB (`hbl.json: "main_thread_stack_size": "0x100000"`). Godot needs a `PLATFORM_THREAD_OVERRIDE` `platform_thread.h` (as `drivers/apple/thread_apple.cpp` does) that sets `pthread_attr_setstacksize` (1-2 MiB), and should run the engine off the main thread or accept the 1 MiB limit.
3. Time: `clock_gettime`, `gettimeofday`, `nanosleep`, `usleep`, `localtime_r`, `strftime` work, but libnx only implements `CLOCK_MONOTONIC`/`CLOCK_REALTIME`, while newlib's `time.h` defines `CLOCK_MONOTONIC_RAW`, so `os_unix.cpp`'s `GODOT_CLOCK` picks `CLOCK_MONOTONIC_RAW` and `_setup_clock()` fails with "OS CLOCK IS NOT WORKING!". One-line patch.
4. `OS::get_processor_count()` returns `std::thread::hardware_concurrency()` which is compiled to return 0 on this libstdc++ (`sysconf` is not even linkable); override it (3 cores usable: `hbl.json` `highest_cpu_id: 2`).
5. Filesystem: everything `file_access_unix.cpp` / `dir_access_unix.cpp` call resolves (`stat`, `opendir`, `rename`, `mkdir`, `fsync`, `ftruncate`, `realpath`, `statvfs`, `mkstemp`, `fchmod`...). Only `<sys/xattr.h>` (unconditional include on non-BSD) is missing, `fsdev` `chmod`/`fchmod` return `ENOSYS`, and `d_type`/`st_dev`/`st_ino` are always 0. `mmap` is absent but nothing in core/drivers/unix uses it. `std::filesystem` is not used by Godot.
6. Process/system: `getenv`/`setenv`/`unsetenv`/`setlocale`/`gethostname`/`getpid`/`signal`/`raise` link; `sigaction`, `getrlimit` (+`struct rlimit`), `uname`, `sysconf`, `pipe`, `mkfifo`, `popen`, `execvp`, `waitpid`, `setsid`, `getentropy`, `fdatasync` do not. `os_unix.cpp` and `file_access_unix_pipe.cpp` need `#ifdef` cuts or a dedicated `OS_Switch` that does not inherit those methods.
7. `dlopen`/`dlsym`/`dlerror`/`dlclose` and `<dlfcn.h>` are absent. Affected: GDExtension loading (soft failure at runtime, cannot be compiled out, base `OS::open_dynamic_library` returns `ERR_UNAVAILABLE`), the non-glibc `_load_iconv()` path in `os_unix.cpp` (compile error, must be cut), and volk/GLAD/sowrap (all SCons-optional: `use_volk=no`, `use_sowrap=no`, `opengl3`/`vulkan` choices).
8. Crash handler: `<execinfo.h>`, `backtrace`, `<link.h>` absent; leave `CRASH_HANDLER_ENABLED` undefined (as `platform/linuxbsd/detect.py` already does for non-glibc without `execinfo=yes`) and stub `CrashHandler`.
9. Networking: libnx ships `sys/socket.h`, `netinet/in.h`, `netinet/tcp.h`, `netdb.h`, `arpa/inet.h`, `net/if.h`, `poll.h`, `sys/ioctl.h`, and implements `socket`/`poll`/`getaddrinfo`/`setsockopt`/`ioctl`/`SO_NOSIGPIPE`/`MSG_NOSIGNAL`; missing are `<sys/un.h>`, `<ifaddrs.h>`, `getifaddrs`, `if_nametoindex`, and `struct ipv6_mreq`. `net_socket_unix.cpp`/`ip_unix.cpp` need small patches or a custom `IPSwitch`; `socketInitialize()` must be called first.
10. Memory: libnx auto-sizes the heap to (TotalMemorySize - UsedMemorySize - 2 MiB) rounded to 2 MiB; under hbloader the heap is handed in via `EntryType_OverrideHeap`, so `__nx_heap_size` is ignored there. Pools on a retail 4 GB unit (Atmosphère mesosphere constants): application pool 3285 MiB, applet pool 507 MiB shared by all applets; so application mode (title override, `__nx_applet_type == AppletType_SystemApplication`) gives roughly 3 GiB and album/applet mode a few hundred MiB minus hbloader's optional `applet_heap_reservation_size`. nxlink: `nxlinkConnectToHost` only `dup2`s the socket onto stdout/stderr; it does not call `setvbuf`, so the port should `setvbuf(stdout, NULL, _IOLBF, 0)` (or `_IONBF`) itself if it wants prompt output.
